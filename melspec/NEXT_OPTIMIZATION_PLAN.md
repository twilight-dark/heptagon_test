# Mel 频谱目标平台结果与后续优化建议

日期：2026-10-04。

## 1. 当前基线与修改边界

当前 `src/melspec.cpp` 已恢复为提交 `c201535`（使用 AVX2 和四点蝶形加速频谱计算）的内容，已核对 Git 对象哈希完全一致。第 4 步的位逆序索引表、FFT 旋转因子表均保留；第 5 步的实数 FFT 恢复系数表也保留。

此前尝试移除第 4 步后，本机一次对比没有出现普遍加速，故已按用户要求回退。这份报告仅记录建议，不代表已实施新的优化，也不产生新的代码提交。

正式算法仅允许修改 `src/melspec.cpp`，保留公开接口、数学语义与输出布局。不修改主程序、头文件、Makefile、验证脚本或数据，不调用音频处理及科学计算库，不识别测试输入。后续临时驱动、日志和构建产物放在 `.validation/`，不提交。

## 2. 用户提供的目标平台结果

平台：Intel Xeon Gold 6338，评测限制为 16 核。

实际编译参数为 `-std=c++17 -Wall -Wextra -O3 -fopenmp -march=native`，链接使用 `-fopenmp`。这与此前本地使用的 `-O2` 存在差异，不能直接用两种构建的耗时判断某个代码变化的收益。

| 用例 | n_fft | n_mels | 频率范围 Hz | 最大绝对误差 | 端到端时间 s | 脚本报告的加速比 |
|---|---:|---:|---|---:|---:|---:|
| default | 2048 | 128 | 0～22050 | 1.46e-3 | 0.127 | 3.152× |
| small_mels | 2048 | 32 | 0～22050 | 7.32e-4 | 0.110 | 3.535× |
| large_fft | 4096 | 128 | 0～22050 | 3.91e-3 | 0.144 | 5.562× |
| narrow_band | 2048 | 128 | 300～8000 | 7.32e-4 | 0.128 | 3.033× |

四个用例全部 PASS；OJ 总分 82.73/100，平均加速比 3.8205×。

原验证判据为逐元素 `abs(actual-expected) <= 1e-4 + 1e-3*abs(expected)`，并非要求所有元素绝对误差都小于 1e-4。主程序两个未使用参数警告不影响本次正确性，不为消除警告扩大修改范围。

## 3. 从结果可以推断什么

### 3.1 Mel 数减少不等于工作量同比例减少

Mel 数由 128 降到 32，耗时由 0.127 秒降至 0.110 秒，约降低 13%。稀疏投影已跳过零权重，全部三角滤波器的非零项总数通常接近频点数的常数倍，不会随着 Mel 数降低四倍。FFT、输入输出等工作也仍存在。

因此，不能把这组结果解释为“Mel 投影优化失效”，也不能期待仅减少 Mel 数就使整个程序加速四倍。

### 3.2 FFT 长度增加，但端到端时间增加有限

FFT 长度从 2048 增至 4096，耗时从 0.127 秒增至 0.144 秒，约增加 13%。这提示端到端时间存在其他重要组成部分，但不足以单独证明读写文件、线程调度或哪一部分占主导。需要分阶段计时确认。

### 3.3 缩窄频带没有明显降低耗时

narrow_band 与 default 的耗时接近。当前仍对所有非负频点执行频谱恢复和功率计算，频率范围缩小只减少部分 Mel 投影工作。可以探索只计算实际会被滤波器使用的功率频点。

### 3.4 加速比与评分需按其实际口径理解

脚本对本程序的计时包含进程启动、PCM 读取与转换、计算、输出转换和写盘；librosa 对比计时只包围频谱计算调用。因此打印的加速比不是严格的纯计算性能之比。

本次未提供 OJ 的完整评分公式，不据此推算还需降低多少时间才能满分。后续优先比较同一构建条件下的程序端到端耗时。

## 4. 按优先级排列的改进策略

### 优先级 1：减少 Mel 点积的调用开销

当前每帧、每个 Mel 频带均通过函数指针调用 `dot_scalar` 或 `dot_avx2`。默认用例约有 `22099*128`，即 283 万次这样的调用。实际开销还取决于编译器能否消除间接调用，需结合生成代码或测量判断。

建议把 SIMD 路径选择移到更外层，让整段 Mel 投影在一个标量或 AVX2 函数中完成。这样更容易内联频带内点积，减少反复进入向量函数及归约的固定开销。

较短滤波器可使用简短标量计算，较长区间使用 SIMD。分界依据通用区间长度及实测成本，不根据公开用例身份选择路径。空区间必须仍输出零。

预期：对默认和窄频带中大量短滤波器可能有效。风险：分支或更复杂的代码布局也可能抵消收益，不能预先保证加速。

### 优先级 2：优化实数频谱恢复与功率计算

当前逐频点通过 `real_bin` 执行端点判断、共轭配对、复数乘法和功率计算。

建议将 DC、Nyquist 等特殊端点单独处理，中间频点改成连续循环，以显式实部和虚部表达计算，再考虑 SIMD。恢复后的数值直接用于功率计算，继续避免保存完整恢复频谱。

编译器可能已经内联 `real_bin` 或优化部分分支，因此重点是使连续数据通路和向量化更明确，不能把源码层的每次函数调用都直接视为机器码层的调用开销。

保持恢复公式、正负号及缩放不变，特别检查 n_fft=1、2、小尺寸，以及一般 FFT 长度。浮点运算重排必须继续通过原误差阈值。

### 优先级 3：只恢复会参与投影的功率频点

根据滤波器非零区间的并集，确定实际需要的功率频点。通常可以先取覆盖所有非零区间的连续范围，避免为边缘未使用频点计算恢复结果和功率。

这个范围由采样率、FFT 长度、Mel 参数计算，与音频内容无关。narrow_band 可能获益较多；全频带场景收益可能有限。

完整的打包复数 FFT 仍需计算，不能直接删掉对应的 FFT 输入或内部频点。只跳过后续不参与 Mel 投影的恢复与功率计算；必要的共轭配对数据仍来自完整 FFT 结果。不得读取未写入的功率缓冲区位置。

### 优先级 4：比较线程数与 OpenMP

目标日志已确认支持 OpenMP，因此之前关于目标构建是否启用 OpenMP 的不确定性已解除。但本地 Makefile 仍未启用，不能直接把两种构建混为一谈。

可在保留相同静态帧区间分配方式的前提下，比较现有 `std::thread` 与 OpenMP，再比较 8、12、16 个工作线程。每次只改变一个因素，避免同时改变线程实现和分配方式。

两种实现都已经具备帧级并行，换为 OpenMP 本身不保证更快。短任务的线程创建、调度和共享资源竞争会影响收益，线程越多也不一定越快。

正式代码若使用 OpenMP，应考虑以 `_OPENMP` 条件保留原构建下可用的路径，不能依赖修改 Makefile。保留线程私有缓冲区，不让多个线程修改同一输出元素或 vector 容量。

### 优先级 5：合并加窗、打包与位逆序搬运

当前先把窗口化采样写入打包 FFT 数组，再按位逆序表交换。可尝试利用现有索引表，把每对加窗后的实数直接写入位逆序目标位置，省掉后续交换过程。

这里应使用半长度复数 FFT 的索引表，而非原始 n_fft 长度的索引。公共 `compute_rfft` 与 Mel 主路径均需保持输入输出语义。

收益来自减少一次独立数据遍历与交换；代价是写入地址不连续。与连续写入再交换相比，哪种更快需要实测，不应直接认定合并总是更优。

### 优先级 6：扩大 FFT SIMD 或增加更高阶蝶形

现有方案使用 AVX2 双复数蝶形，并融合了最前面的两级。后续可以考虑更多阶段融合、更高阶蝶形或其他适合目标机器的 SIMD 布局。

这类调整牵涉数据重排、寄存器占用和更复杂的正确性检查，暂不优先重写整套 FFT。更宽向量或更高阶蝶形也不意味着端到端时间一定下降，应先处理前面的明确开销。

## 5. 建议的验证方式

1. 保留 `c201535` 作为本轮基线，先验证优先级 1，再验证优先级 2，不一次混入多个策略。
2. 在独立验证目录使用平台相同的 `-O3 -fopenmp -march=native` 编译选项做代码对比；不同 CPU 的 `-march=native` 会生成不同指令，因此本机结论仍需目标平台确认。
3. 继续使用原四项正确性验证。涉及 FFT 恢复、SIMD 和索引变化时，补充小尺寸及边界对照。
4. 在独立副本或验证驱动中简单区分读入、Mel 计算、写出耗时，不修改正式 main.cpp 或原始评测计时逻辑。
5. 单次测试适合初筛，几个百分点的变化可能属于波动；需要确定保留版本时，再进行适度重复比较。
6. 如果端到端时间主要受输入输出影响，应降低对继续优化 FFT 的收益预期。既有单文件约束下不修改主程序读写流程。

下一步建议：仅尝试外提 Mel 点积的 SIMD 分派，保留 FFT、预计算、线程划分及接口不变，便于判断收益来源。
